Operational Governance & Terms of Service

Definitive administrative governance framework, operator conduct code, and access guidelines governing the deployment and live operation of the A.T.L.A.S. surveillance dashboard.

Authorized Clearance

Access is restricted strictly to designated server administrators and staff. Link credentials must never be shared or leaked publicly.

Proportional Moderation

In-game moderation actions (kicks, bans, inventory clears, teleports) must adhere strictly to established server community rules.

Ethical Audio Surveillance

Spyglass voice interception must be used solely to investigate rule violations, griefing, or harassment. Zero permanent recording.

Anti-Abuse & Rate Limits

Automated IP defense and rate limiters actively protect endpoints. Brute-force token attempts trigger automated socket closures.

Scope of Service & Acceptance of Terms

By accessing, connecting to, or using the A.T.L.A.S. Surveillance Dashboard (via web browser, WebSocket client, or API endpoint), you acknowledge that you have read, understood, and agree to be bound by these Terms and Conditions.

Access to this dashboard is granted exclusively as a privilege to authorized server staff, moderators, and administrators for the express purposes of server maintenance, live observation, anticheat investigation, and community policy enforcement.

Exclusive Server Jurisdiction
This software operates directly on the Minecraft server's host machine. The server owner maintains ultimate authority over access clearances, permission tiers, and all moderation decisions made using this suite.
02

Authorized Operator Conduct & Credential Hygiene

Every operator granted access to this surveillance instance must abide by the following standards:

  • Token Confidentiality: Generated access URLs contain high-entropy session tokens. Operators must treat these links as sensitive credentials and never post or leak them in public chats, streams, or Discord channels.
  • No In-Game Abuse: Using live player radar coordinates, inventory telemetry, or block activity for unfair in-game advantages (e.g., raiding without cause, stream sniping, metagaming in survival or factions) is strictly prohibited.
  • Audit Accountability: All remote command executions, moderation dispatches, and queued offline player actions are logged with the initiating operator's identity.
  • Immediate Revocation: If an operator suspects a dashboard link has been exposed, they must run /atlas unlink immediately to invalidate the instance.
03

Voice Telemetry & Live Audio Broadcasting Standards

The integrated voice subsystem provides live proximity surveillance and administrative two-way voice transmission via Simple Voice Chat integration. Operators agree to the following terms:

  • Investigative Purpose Only: The Spyglass Audio Monitor is intended to verify reported toxicity, harassment, hate speech, or illicit collusion. It must not be used to intrude upon private player areas without cause.
  • No Secondary Audio Recording: Operators must not use third-party desktop audio capturing software to record or publish players' private voice chat without their informed consent.
  • Broadcast Decorum: When using the dashboard microphone for server-wide broadcasts or direct player communications, operators must maintain professional decorum and adhere to community guidelines.
  • Zero Retention Policy: A.T.L.A.S. processes voice frames solely in volatile memory. Operators must not attempt to alter the daemon to create permanent acoustic recordings.
Voice Transmission Notice
Broadcast audio streams are transmitted directly to all connected players with Simple Voice Chat. Ensure your microphone is muted when not actively issuing administrative announcements.
04

Remote Moderation Actions & Ledger Execution

A.T.L.A.S. empowers operators to execute live in-game actions directly from the web interface, including kicking, banning, clearing inventories, and issuing console commands:

  • Proportional Enforcement: Penalties applied must be proportionate to the verified infraction. False or malicious penalties will result in immediate revocation of staff clearance.
  • Offline Action Queue: Actions targeted against offline players are stored in a persistent local ledger (pending_actions.json) and executed atomically when the target player reconnects.
  • Irreversibility of Destructive Actions: Inventory clears and player data wipes are permanent. Operators must verify player identities before executing destructive commands.
05

System Security, Rate Limiting & The /atlas unlink Mandate

To maintain the integrity and stability of the server, the following technical restrictions are enforced:

  • No Exploitation: Users shall not reverse engineer, tamper with WebSocket payloads, or attempt to bypass session validation filters.
  • Automated IP Rate Defense: Excessive requests, failed handshake flooding, or brute-force attempts will trigger automated rate limiting and connection drops.
  • The Unlink Mandate: To close an active dashboard instance, operators can execute /atlas unlink (or /atlas close). This revokes all link tokens, clears session cookies, and immediately terminates all open WebSocket connections.
Security Violation Consequences
Unauthorized attempts to probe internal WebSocket endpoints or flood tile renderers will result in immediate IP banning from the Minecraft server and web interface.
06

Disclaimers, Warranty & Uptime Limitations

A.T.L.A.S. is provided as an administrative aid "as is" and "as available". The authors and server management make no warranty that dashboard feeds, map tile renderings, or voice streams will be uninterrupted, error-free, or compatible with all network topologies.

In the event of server restarts, network disconnects, or daemon reloads, active WebSockets will temporarily close and reconnect once the server daemon resumes.

07

Frequently Asked Questions for Operators

Who is permitted to receive a dashboard link?
Only individuals with verified administrative clearance (atlas.admin permission or server console access). Links must never be shared with regular players or non-staff members.
What happens if an admin runs /atlas unlink?
Executing /atlas unlink immediately invalidates all active link tokens, wipes all session registry records, and disconnects all connected WebSocket browsers with a security termination notice.
Can players request data removal or audit logs?
Yes. In accordance with community standards and our Privacy Policy, players can contact server leadership through official channels to request information regarding any offline cached records stored on the server disk.
